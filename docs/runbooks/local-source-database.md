# Local Source Database Runbook

## Purpose

This runbook starts the local infrastructure and restores the Postgres Professional Airline Demo Database into a local PostgreSQL container.

The source dump is the official one-year `demo-20250901-1y.sql.gz` release. It is approximately 558 MB compressed (about 5.4 GB after restore) and creates a database named `demo` containing the `bookings` schema. The dump itself deletes and recreates `demo`, so the restore script refuses to run if that database already exists.

The current dump was generated by PostgreSQL 17.5 and contains the `transaction_timeout` setting. The restore script explicitly removes only that unsupported configuration statement so that the official data can be restored into the supported local PostgreSQL 15 runtime.

Source: <https://postgrespro.com/community/demodb>

## Prerequisites

- Docker Desktop is running.
- Copy `.env.example` to `.env` and replace all placeholder passwords.
- At least 7 GB of free disk space for the restored one-year database and local service volumes.

## Start local services

```powershell
Copy-Item .env.example .env
docker compose up -d postgres minio minio-init mlflow
docker compose ps
```

Expected services:

- PostgreSQL: `localhost:15432`
- MLflow: `http://localhost:5000`
- MinIO API: `http://localhost:9000`
- MinIO console: `http://localhost:9001`

## Download and restore source data

```powershell
.\scripts\download-demo-database.ps1
.\scripts\restore-demo-database.ps1
```

The archive is stored under `data/source/`, which is Git-ignored. The restore script makes no destructive decision automatically: if `demo` exists, it stops and asks you to inspect or intentionally remove the existing local data yourself.

## Verify source access

```powershell
docker compose exec postgres psql -U flightops_admin -d demo -c "SELECT COUNT(*) FROM bookings.flights;"
docker compose exec postgres psql -U flightops_app -d demo -c "SELECT COUNT(*) FROM bookings.flights;"
```

The second command verifies the restricted project role can read `bookings`. Project-owned schemas are `staging`, `analytics`, and `ml`.

See [source data inventory](../source-data-inventory.md) for the inspected snapshot range, status distribution, and table sizes.

## Stop services

```powershell
docker compose down
```

This preserves named Docker volumes. Do not use `docker compose down -v` unless you intentionally want to remove all local PostgreSQL and MinIO data.
